# 급할수록 놓치는 카드 — 편의점 무인 ATM 반환 순서 프로토타입

Chapter 01~06에서 기획한 "편의점 무인 ATM 카드·현금 반환 순서 개선 프로젝트"를 Claude Code로 구현한 웹 프로토타입입니다.
기존 방식(A)과 개선안(B)을 같은 과업으로 체험하게 하고, 카드 회수 여부·소요 시간·설문 응답을 기록해 두 조건을 비교합니다.

## 1. 프로젝트 목적

급하게 출금하는 이용자가 현금을 먼저 받으면 목표가 끝났다고 느껴 카드를 두고 가는 사후 완료 오류(post-completion error, Byrne & Bovair, 1997)를 줄이는 것이 목표입니다.
실제 ATM 하드웨어를 바꿀 수 없으므로(Ch03 제외 범위), Ch02~03에서 계획한 Wizard-of-Oz 시나리오 프로토타입을 웹 화면으로 옮겨 사용자 테스트에 쓸 수 있게 만들었습니다.

**핵심 문제 (Ch02 최종 문제문장)**
> 급하게 편의점 무인 ATM에서 출금하려는 이용자는 현금과 카드를 모두 챙겨 자리를 뜨려 하지만, 시스템이 반환 순서를 사전 안내함에도 기기마다 그 순서 자체가 달라 급한 상황에서는 안내를 놓치기 쉬워, 현금을 먼저 받으면 카드 회수라는 남은 절차를 잊어버릴 위험을 경험한다.

**검증할 가설 (Ch03)**
- H1. 카드를 현금보다 먼저 반환하도록 순서를 통일(물리적 강제)하면 카드를 두고 가는(또는 두고 갈 뻔한) 빈도가 줄어든다.
- H2. 반환 순서를 색상·아이콘으로 강조해 안내하면 급한 상황에서도 순서를 더 잘 예측한다.

## 2. 사용자 요구사항과 구현 대응

|---|---|---|---|
| R1 | 반환 순서를 카드 우선으로 통일하고 구조적으로 강제 (Frame 3) | E01, E03, C02, I02 | 조건 B: 카드가 먼저 나오고, 카드를 가져가기 전까지 현금 출구가 잠김 |
| R2 | 글을 읽지 않아도 알아채는 순서 안내 (Frame 1) | C01, I01 | 조건 B: ① 카드 → ② 현금 아이콘 배너, 처리 중·반환 화면에서 반복 |
| R3 | 미회수 경고음·화면 알림 | C02 | 3초 미회수 시 경고음(Web Audio), 자리를 뜨려 하면 붉은 경고 화면 |
| R4 | 순서 강제로 생길 새 위험(현금 방치) 대비 | Ch02 Frame 3 확인할 가정 | 조건 B: 현금도 3초 미회수 시 경고 |
| R5 | 출금 상단 배치, 낯선 용어 설명 (Frame 2, 보조 문제) | E02, C03, I03 | 조건 B 메뉴: 현금 출금을 맨 위에 가장 크게, 자주 쓰는 3개(계좌이체·예금조회·현금 입금)를 크게, 나머지 6개는 기타 거래(OTHERS) 화면으로 묶음. 모든 메뉴에 한 줄 설명 |
| R6 | 가설 검증 지표 측정 | Ch03 §5, Ch04 | 카드 회수 성공률, 두고 떠나려 한 비율, 소요 시간, 5점 척도 설문, 시간순 기록, CSV |
| R7 | 급한 상황 재현 | Ch04 방법 2의 실험실 효과 보완 | 대기자 표시, 경과 시간, 12초·25초 뒤 재촉 문구 |

## 3. 주요 기능

**테스트 화면**
- 연구자 패널: 참여자 가명 ID, 조건(A / B / 무작위 배정), 시간 압박 재현, A 조건 경고음 켜기·끄기
- ATM 시뮬레이터: 카드 넣기 → 순서 안내 → 비밀번호(물리 키패드) → 메뉴 → 금액 → 처리 중 → 카드·현금 반환
  - 조건 A: 시행마다 반환 순서가 무작위, 안내는 작은 글씨 한 줄, 같은 크기 메뉴 12개, 구석의 작은 "입력완료" 버튼
  - 조건 B: 항상 카드 먼저, 현금 출구 잠금, 아이콘 안내, 출금 상단 배치와 기타 거래(OTHERS) 묶음, 카드·현금 모두 경고
- "자리 떠나기" 버튼: 걸어 나가는 행동을 대신함. 카드나 현금이 남아 있으면 경고 후 4초 안에 "돌아가서 챙기기"를 누르지 않으면 두고 간 것으로 기록
- 시간순 관찰 기록: Ch05 관찰기록 양식처럼 모든 행동과 시스템 반응을 0.1초 단위로 자동 기록 (메뉴 오선택, 화면 단계에서 키패드를 누른 오조작 포함)
- 거래 직후 설문: 예측 가능성·불안감 5점 척도, 좋았던 점과 걱정되는 점 (Ch04 파일럿에서 수정한 질문)

**결과 화면**
- 조건별 지표 비교 막대, H1·H2·실패 조건 판정 메모
- 시행별 기록 표, CSV 복사(스프레드시트에 붙여 넣기용), 전체 삭제(화면 안 확인 단계)
- 저장된 기록이 없을 때는 "가상 예시 데이터" 표시를 달고 예시를 보여 줌 (실측값 아님)

**기획 요약 화면**
- 문제문장, 근거(E01~E03, C01~C03), 요구사항 대응표, 조건 설명, 가설, 한계, 참고문헌

## 4. 실행 방법

- 배포 링크를 열면 바로 사용할 수 있습니다.
- 내 컴퓨터에서 실행하려면 `index.html`을 브라우저로 엽니다.
- 경고음은 브라우저 정책상 첫 클릭(카드 넣기) 이후부터 납니다. 소리를 켜 두세요.
- 실제 카드번호·비밀번호는 쓰지 않습니다. 비밀번호는 아무 숫자 4자리입니다.
- 테스트 기록은 그 브라우저에만 저장됩니다. 테스트를 마치면 결과 화면의 **CSV 복사**로 옮겨 두세요.

## 5. 한계

- 실제 ATM이 아니라 웹 화면입니다. 손으로 카드를 뽑는 동작과 걸어 나가는 동작을 버튼으로 대신합니다.
- 참여자 3~5명 규모의 방향 확인용이며 통계 검정을 하지 않습니다.
- 4초 경고 지연, 3초 미회수 경고는 설계 가정값입니다. 실제 기기의 값은 확인하지 않았습니다.
